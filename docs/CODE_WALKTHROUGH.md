# Разбор кода

## `app/config.py`

Хранит строку подключения к БД. Значение `DATABASE_URL` берётся из окружения при старте
процесса; для локального запуска предусмотрен SQLite по умолчанию.

## `app/db.py`

Определяет SQLAlchemy `Base`, фабрику сессий и FastAPI-зависимость с гарантированным закрытием
сессии. `init_db` создаёт таблицы и идемпотентно добавляет три тарифа: поиск идёт по уникальному
`title`, поэтому перезапуск не создаёт дубликаты.

## `app/enums.py`

Содержит строковые перечисления способов оплаты и статусов. Они ограничивают допустимые
значения на границе API и позволяют хранить в БД понятные строковые значения.

## `app/models.py`

Описывает таблицы `Tariff` и `Payment`. Суммы используют `Integer`; поле `idempotency_key`
уникально, а время создания формируется в UTC. `schedule` — JSON-массив платежей или `null`.

## `app/schemas.py`

Содержит Pydantic-модели входных и выходных данных. Валидатор разрешает рассрочку только на 3,
6 или 12 месяцев и запрещает её параметры для других способов оплаты.

## `app/security.py`

Проверяет HMAC-SHA256 по исходному телу вебхука. Секрет читается в момент запроса, что удобно
для безопасной смены значения и тестов; `compare_digest` выполняет сравнение без утечки времени.

## `app/services/pricing.py`

Здесь чистые функции цены. Промокод нормализуется, скидка рассчитывается целочисленно, а
остаток от деления рассрочки распределяется по первым платежам.

## `app/services/statuses.py`

Фиксирует единственную таблицу допустимых переходов. `can_transition` не допускает
самопереходы и позволяет одинаково применять правило из роутера и тестов.

## `app/services/payments.py`

Содержит операции с платежами: поиск, создание, фильтрацию и смену статуса. При создании
уникальный ключ защищает от параллельных дублей: после `IntegrityError` транзакция откатывается,
а исходная запись читается и возвращается повторному запросу.

## `app/routers/tariffs.py`

Тонкий роутер `GET /tariffs`. Он читает тарифы через зависимость сессии и всегда сортирует их
по `id`, поэтому ответ детерминирован.

## `app/routers/payments.py`

Содержит создание, получение и список платежей. Роутер проверяет повторный ключ до расчёта
тарифа и меняет код ответа на 200 для повторного запроса; детали расчёта остаются в сервисе.

## `app/routers/webhooks.py`

Принимает уведомление банка после проверки подписи. Успешный и конфликтный ответы создаются
через `JSONResponse`, чтобы их тела были ровно `{"result":"ok"}` и
`{"error":"invalid_transition"}`, а не стандартный `detail`.

## `app/main.py`

Создаёт приложение и подключает роутеры. Lifespan вызывает инициализацию схемы и тарифов при
обычном старте сервера; в тестах та же функция вызывается напрямую из фикстуры.
